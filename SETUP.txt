ALLIANCE KNOWLEDGE REPOSITORY
Google setup for the current deployment

1. Sign in as the owner who deploys the current web app. Open the standalone Alliance Knowledge Repository project in Apps Script. Verify the signed-in email in Google. The /exec URL alone does not identify the deployment owner.

2. Save the revised Code.gs and its appsscript.json manifest in that project. Run authorizeDeviceUploads in the Apps Script editor as the deployment owner. In Services (+), enable Drive API v3 (Drive) and Google Sheets API v4 (Sheets). If the project uses a standard Google Cloud project, enable those APIs there too.

3. Set UPLOADER_KEY_SHA256 in Script properties to the lowercase hexadecimal SHA-256 digest of one randomly generated uploader key. Give the original key privately to the uploader. This key permits upload, search and keyword management. Google Drive sharing controls who can open the stored files.

4. For a new empty index, start with SHEET_ID and PARENT_ID unset in this project. If they already exist, inspect them before proceeding. Run prepareFreshRepository from the editor as the deployment owner and approve Google's authorization prompts. The function creates a new private spreadsheet and parent folder in that account and saves their IDs as Script properties. It then runs setupEverything to initialize the tabs and seven libraries. Retrying reuses the saved IDs. The original index and files stay in place.
   If using explicitly provisioned empty resources, set their IDs instead and run setupEverything once.
   NEVER RUN resetForGoLive for this rollout.
   Share the new repository folder with authorized team members who need to open the files. Keep the index restricted to its maintainers.

5. Rehearse the release before changing production. Create a temporary web-app deployment of this version, execute as the deploying owner and allow access from the GitHub Pages form. Use its /exec URL in a local copy of index.html for the smoke test in GO_LIVE_CHECKLIST.txt. When ready, edit the original web-app deployment under Deploy > Manage deployments, select New version, and deploy. This keeps the current /exec URL configured in the release. Coordinate that change with the GitHub Pages release because the previous frontend uses a different API.

6. For the new Google account follow DRIVE_HANDOVER.md to keep the current spreadsheet and public URL.
